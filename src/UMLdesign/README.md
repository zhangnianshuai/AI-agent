## 时序图


一、简历上传
![alt text](img/简历上传.png)
（已经登录，获取到用户id）
1. 用户上传简历.pdf
2. 前端校验 pdf，提取文本
3. 前端 post：resume/load + 文本
4. 后端调用大模型解析文本，输出：姓名，年龄，性别，工作经验，毕业院校 list，项目经历 dict {list}，掌握技能，自我评价
5. 传入前端对应位置展示给用户解析内容
6. 用户修改完成，点击上传简历
7. 前端 post：resume/upload+json
8. 后端将 {user_id,name+age+sex，work_year,skills, 自我评价} 存入 resume 表，education 存入教育表 (education_id,user_id)，项目经历存入项目表（project_id,resume_id），返回上传结果给前端
9. 前端返回简历上传成功

二、岗位创建
![alt text](img/岗位设置.png)
1. 企业输入岗位基本信息 {岗位名称，岗位简介，岗位关键词，工作年限} 给前端
2. 前端获取信息，传递进入后端
3. 后端进行违规检测
4. 后端将信息存储到 mysql（job_id，company_id），并且把信息发送给 LLM 总结出用户画像 (job_id 做 pk)存入milvus, 将结果返回前端
5. 前端将结果返回给企业

三、面试官配置
![alt text](img/面试官配置.png)
1. 企业点击获取公司岗位列表  
2. 前端根据 cookie 存有 user_id 发送给后端  
3. 后端根据 user_id 去 mysql 的 user-company 表找到公司 id 列表，根据公司 id 去 mysql 的 company-work 表和 work 表找到岗位列表  
4. 返回岗位列表给前端，前端展示给企业，企业选择对应岗位，点击编辑  
5. 后端根据岗位 id 去查找岗位详细信息，返回给前端，前端展示  
6. 企业点击配置面试官  
7. 输入配置信息（每次回答参考多少题：ranker_params，指定相似度：score_threshold，最少问答题目数：question_nums）  
8. 传入后端，后端将 {配置 + 联合索引(岗位 id+公司 id)} 存入 mysql 的 agent-config 表  

四、用户选择岗位
![alt text](img/用户选择岗位时序图.png)
1. 用户点击进入岗位广场并开始浏览岗位  
2. 前端页面向后端发送 GET /positions 请求，获取所有已发布的岗位信息
3. 后端接收到请求后，向数据库查询所有岗位数据（含岗位名称、薪资、企业、招聘状态等）
4. 数据库将查询结果返回给后端，后端再将数据返回给前端
5. 前端接收到数据后，在页面中以列表或卡片形式展示所有岗位（含匹配度标签）
6. 用户输入企业名称、岗位类型或行业等条件，对岗位进行筛选
7. 前端将用户输入的搜索条件封装成请求，发送给后端,后端解析搜索条件，在数据库中进行模糊匹配或精确查询
8. 数据库将符合条件的结果返回给前端，前端展示筛选后的岗位列表
9. 前端向后端发送 GET /positions/recommend 请求，同时携带用户简历画像向量（教育背景、技能关键词、项目经验等）,后端接收请求后，将用户简历画像与各岗位的能力维度要求进行匹配计算，生成每个岗位的匹配度分数
10. 后端将所有岗位按匹配度从高到低排序，将排序后的推荐列表返回给前端,前端接收到推荐列表后，在页面中对匹配度高的岗位进行高亮标注，并优先展示在列表顶部
11. 用户点击某个岗位的卡片，希望查看该岗位的完整信息,前端向后端发送 GET /positions/{id}/detail 请求，其中 {id} 为该岗位的唯一编号,后端根据岗位编号，在数据库中查询该岗位的完整JD信息（含岗位职责、任职要求、薪资待遇、企业信息等）
12. 数据库将查询结果返回给后端，后端再将数据返回给前端,前端接收到数据后， 在详情弹窗或详情页中完整展示该岗位的所有信息,用户阅读完岗位详情后，确认选择该岗位，点击"选择该岗位"按钮
13. 前端向后端发送 POST /positions/select 请求，携带用户编号和岗位编号,后端将用户编号、岗位编号、选择时间等信息写入 selection_record 选岗记录表，同时将用户状态更新为"待面试"
14. 数据库写入完成后，将操作成功结果返回给后端，后端再返回给前端,数据库写入完成后，将操作成功结果返回给后端，后端再返回给前端

五、参加面试
![alt text](img/用户参加面试时序图.png)
1. 用户选择目标岗位并点击“开始面试”
2. 前端向后端发送开始面试请求，携带用户编号、面试编号和岗位编号等信息
3. 后端校验用户是否具备面试资格，包括用户状态、面试状态、简历、岗位面试官配置和企业 RAG 题库等
4. 校验通过后，后端创建面试会话，将面试状态更新为“进行中”，并保存到数据库
5. 后端整合用户简历、岗位要求、面试官配置和企业知识库信息，请求大模型生成第一道面试题
6. 大模型通过 Agent 编排、RAG 检索和模型推理生成题目，后端保存题目并返回前端展示
7. 用户回答当前题目，前端将题号和答案提交给后端，后端保存用户答案
8. 后端调用大模型对答案进行评分和分析，得到分数、评语以及是否需要追问等结果
9. 后端根据评估结果返回追问题目或下一道题，前端继续展示，循环执行“答题—评分—追问或下一题”，直到全部题目完成
10. 用户点击“结束面试”，后端汇总所有题目、答案和评分，请求大模型生成综合评价报告，保存面试结果并将状态更新为“已完成”，最后由前端向用户展示总分、评价和改进建议
